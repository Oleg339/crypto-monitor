# 🧪 Тестирование парсера сигналов Трейдера 3

Этот документ описывает, как тестировать парсер торговых сигналов с реальными сообщениями из Telegram канала.

## 🎯 Обзор

Система включает четыре способа тестирования парсера:

1. **Unit тесты** (`cmd/tradebot/parser_test.go`) - автоматизированное тестирование с детальным выводом структуры
2. **Live Demo** (`cmd/parse_demo/main.go`) - парсинг реальных сообщений с подробным анализом каждого этапа
3. **Мониторинг** (`cmd/parser_tester/main.go`) - быстрый мониторинг канала со статистикой
4. **Quick Parse** (`cmd/quick_parse/main.go`) - интерактивная проверка одного сообщения

## ⚙️ Настройка

### Необходимые переменные окружения в `.env`:

```bash
# Telegram API credentials (получить на https://my.telegram.org)
TELEGRAM_APP_ID=12345678
TELEGRAM_APP_HASH=your_app_hash_here
TELEGRAM_PHONE=+1234567890

# Канал трейдера 3
TRADER3_CHANNEL=-1003722628653
TRADER3_THREAD_ID=8
```

### Получение Telegram API credentials:

1. Зайдите на https://my.telegram.org
2. Войдите с вашим номером телефона
3. Перейдите в "API development tools"
4. Создайте новое приложение
5. Скопируйте `App api_id` и `App api_hash`

## 🧪 Способы тестирования

### 1. Unit тесты (рекомендуется для CI/CD)

```bash
# Запуск всех тестов
go test ./cmd/tradebot -v

# Запуск только парсер тестов
go test ./cmd/tradebot -v -run TestParse

# Бенчмарк производительности
go test ./cmd/tradebot -bench=BenchmarkSignalParsing

# Тест с реальным каналом (требует интерактивного ввода кода)
go test ./cmd/tradebot -v -run TestParseRealTelegramMessages
```

### 2. Live Demo с детальным анализом (рекомендуется!)

```bash
# Собрать и запустить
go build -o parse_demo ./cmd/parse_demo
./parse_demo
```

#### Что делает Live Demo:
- 🎯 **Подключается к реальному каналу** Трейдера 3
- 📝 **Показывает каждое сообщение** по мере поступления  
- 🔍 **Анализирует пошагово**: фильтры → регулярки → структура → алерт
- 📊 **Детальная структура**: все поля ParsedSignal с расчетами R:R
- 🎉 **Статистика в реальном времени**: сколько сообщений спаршено

### 3. Быстрый мониторинг канала

```bash
# Собрать и запустить  
go build -o parser_tester ./cmd/parser_tester
./parser_tester
```

#### Что делает мониторинг:
- ⚡ **Быстрый обзор** всех сообщений
- 📊 **Итоговая статистика** по завершению
- 🚀 **Минимальный вывод** для производительности

### 4. Интерактивная проверка одного сообщения

```bash
# Собрать и запустить
go build -o quick_parse ./cmd/quick_parse  
./quick_parse
```

#### Что делает Quick Parse:
- 📝 **Вставьте любое сообщение** из Telegram
- 🔍 **Мгновенный анализ** парсинга
- 📊 **Полная структура** результата
- ⚡ **Без подключения к Telegram** - работает оффлайн

## 🔍 Что тестирует парсер

### ✅ Валидные сигналы (должны парситься):

```
[trader#3] 🌹SIGNAL ID: #2133🌹
COIN: $FIL/USDT (2-5x)
Direction: LONG

ENTRY: 1.040 - 1.050

TARGETS: 1.100 - 1.150 - 1.225 - 1.300

STOP LOSS: 0.950

Technical analysis description...
```

### ❌ Отфильтровываемые сообщения:

1. **GEM сигналы** - содержат "GEM SIGNAL"
2. **Сообщения о прибыли/убытках** - содержат "% PROFIT" или "% LOSS"
3. **Обычные сообщения** - без структуры сигнала
4. **Неполные сигналы** - отсутствуют обязательные поля

### 🎯 Проверяемые компоненты:

- **Signal ID** - извлекается номер сигнала
- **Symbol** - конвертируется `$FIL/USDT` → `FILUSDT`
- **Direction** - `LONG` или `SHORT`
- **Entry zone** - диапазон входа `1.040 - 1.050`
- **Stop Loss** - уровень стопа `0.950`
- **Take Profits** - все таргеты `1.100 - 1.150 - ...`
- **Calculations** - процентные соотношения R:R

## 🐛 Отладка

### Проблемы с авторизацией:

1. Проверьте правильность `TELEGRAM_APP_ID` и `TELEGRAM_APP_HASH`
2. Убедитесь что номер телефона в международном формате (`+1234567890`)
3. Удалите файлы сессий: `rm session_*.json`

### Не получает сообщения:

1. Проверьте правильность `TRADER3_CHANNEL` и `TRADER3_THREAD_ID`
2. Убедитесь что ваш аккаунт подписан на канал
3. Проверьте что канал активен и отправляет сообщения

### Не парсит сигналы:

1. Запустите с флагом `-v` для детального логирования
2. Проверьте формат сообщений - он может измениться
3. Обновите регулярные выражения в `userbot.go` при необходимости

## 📊 Метрики производительности

Типичные показатели:
- **Parse rate**: 15-25% (не все сообщения - торговые сигналы)
- **Performance**: ~10,000 парсингов/сек на обычном железе
- **Memory**: ~1MB на 1000 сообщений

## 🔄 Обновление парсера

При изменении формата сигналов трейдера:

1. Обновите регулярные выражения в `userbot.go`
2. Добавьте новые тест-кейсы в `parser_test.go`
3. Запустите полное тестирование
4. Обновите документацию
